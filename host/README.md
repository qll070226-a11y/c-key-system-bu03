# C题 BU04 PDOA 定位诊断上位机

该工具读取 ESP32-S3 USB 串口输出的 C_KEY_DIAG_V3（兼容旧版V2），用于观察 BU04 PDOA
基站给出的原始距离与角度，以及固件完成校正、滤波和门锁坐标换算后的结果。

## 端口关系

- COM25：当前 BU04-Kit 的 USB 测距数据口，输出 31 字节二进制 Hex 帧。
- ESP32 诊断串口：上位机应连接这个端口，通常是 CH343，编号以设备管理器为准。
- BU04 AT 串口：只用于配置和烧写，不用于本上位机。

正式整机连接时，BU04 UART2_TX 接 ESP32-S3 GPIO18，两者 GND 共地。ESP32
解析二进制帧后，才会在自己的 USB 串口输出上位机能够读取的文本诊断帧。
因此不能直接在 GUI 中选择 COM25 期待看到 C_KEY_DIAG_V3/V2。

## 安装与启动

推荐 Windows Python 3.13。首次运行：

    cd host
    .\setup.bat

依赖安装在 host/.venv，不会修改系统 Python 包。启动：

    .\run.bat

选择 ESP32 的 CH343 串口，波特率 115200，点击“连接”。连接 GUI 前可检查：

    .\check_serial.bat COM21 --seconds 8

把 COM21 换成 ESP32 当前端口。返回 diagnostics 大于 0 且 parse_errors
为 0，表示固件和上位机协议匹配。

没有硬件时可启动演示模式：

    .\run.bat --demo

## 页面说明

### 实时诊断

- 距离图：原始距离、线性校正距离和滤波距离。
- 角度图：BU04 原始 PDOA 角度和固件滤波角度。
- 边界图：标签到门锁外壳的距离，即天线中心距离减去 0.30 m。
- 二维图：按滤波距离和角度换算的标签位置与移动轨迹。
- 标签地址：当前配对标签短地址，现用标签应为 0x6E19。
- 帧质量：BU04 正确帧、坏帧及上位机观察到的序号缺口。

### 定点采集

1. 输入标签相对 BU04 天线中心的真实 X/Y。正前方是 Y>0，右侧为 X>0。
2. 基站高度和标签高度均指 UWB 天线中心离地高度。
3. 每个点建议采集至少 300 帧。
4. 距离建议覆盖 1 m、2 m、3 m；角度建议覆盖 0°、±15°、±30°、±45°。
5. “计算标定”只拟合 BU04 距离比例和零偏；角度零偏从汇总表的
   “滤波方位角中位误差”判断。

上位机计算标定参考距离时会使用两项高度输入，公式为：

    sqrt(X² + Y² + (标签高度 - 基站高度)²)

当前固件实时判区不做高度补偿，仍直接使用 BU04 测得的空间距离。

标定结果不会自动写入固件。应先检查 MAE、最大误差和独立验证点，再更新
sdkconfig.defaults。

### CSV

“记录CSV”保存每帧 PDOA 数据和当前测点信息，文件可通过“回放”重新载入。
host/output/ 默认不提交 Git，避免把大量现场日志混入源码。
